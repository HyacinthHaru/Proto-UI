# S4 React module delivery and early loading

All browser attempts selected the same Chinese S4 case on the static diagnostic artifact generated from signed source `5d4f911370ca5e9cb4e4a17f20eca0b1945d6862`. Both internal Matrix routes were enabled for the local build only. Each run served identical Chinese HTML with all 1,268 previews. Chrome 156.0.8078.79, Node 24.21.0, pnpm 10.32.1 and one Vitest worker stayed fixed. The original readiness condition retained 60,000 ms and the test retained its 150,000 ms outer limit.

- In `baseline-wire.json`, the three React entry modules and the shared React chunk each received HTTP 200 and a Chrome Network loading completion event. The relevant React Accordion owner entered its render and runtime wait. No import return was observed by the original outer failure.
- In `native-import-dispatch.json`, Vite logged all three native import dispatches at about 13.82 seconds. The four React assets and the preload helper carried the diagnostic bytes recorded in `asset-overlay-bytes.json`. None of the four React body entry markers appeared before the original timeout. This leaves module evaluation and scheduling unresolved. Chrome event timestamps and delivery order have different semantics. These receipts establish presence of each network event and do not measure an exact response-to-evaluation interval.
- In `early-runtime.json`, a diagnostic native script requested the existing compiled runtime after DOMContentLoaded at about 5.07 seconds. The three imports returned at about 22.86 seconds. The observed React Accordion owner joined the runtime at 65.84 seconds and published at 68.07 seconds. The last delivered original readiness sample identified the Vue Base Accordion at index 2 as the first missing owner. The whole-page run still hit its 150-second outer limit and did not enter the Dialog journey.
- `attempts.json` retains the preliminary callback injection that Vitest rewrote to an undefined SSR helper and the invocation that failed before launching the browser because of a wrong config path.

The native-script comparison changes when one loader is requested. The observation does not establish a general compiler bug or justify changing website startup behavior. The compiled assets and test sources were restored after their respective observations.
