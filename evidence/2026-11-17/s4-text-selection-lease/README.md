# Preserve selected input text during content moves

Signed candidate `ca3dff46432109bbe7a10b76ad19df4d5263ffb0` captures the focused native input or textarea's selection endpoints and direction before a composition move. It restores that range after restoring the document Selection, provided the same connected text control still owns focus and supports text selection. This follows the existing Website clipboard restoration pattern.

The actual Chromium control exposed the original defect. Moving the focused authored control restored focus and its value, but the subsequent document Selection restoration changed its selected range from 3–8 to 0–0. Both input and textarea controls lost their forward/backward direction. Four new unit cases failed on the parent, with ten existing cases passing; the final source passed 254 tests across six related suites.

The native source fixture exercised ten scenarios against the parent and candidate. Candidate input/textarea forward/backward ranges retained 3–8 and their direction. Empty document selection, forward/backward page text ranges, cross-owner endpoints and registered retired-wrapper endpoints also passed. The same scenarios then loaded the actual static site's emitted native-content lease module and all ten candidate scenarios passed again. The unchanged parent control retained its four field-selection failures in both comparisons.

An earlier uncommitted atomic-move experiment used Chromium's moveBefore API to avoid Selection reads for an authored source. Its 253 unit tests passed and the ordinary empty fixture avoided a layout flush. The real browser nevertheless lost forward, backward and cross-owner page Selection endpoints. Its registered-wrapper fallback remained correct. That implementation was archived and removed. The original Chinese full matrix under the temporary first-move control still exceeded the readiness limit. This negative result is preserved rather than treated as a product optimization.

The exact candidate built 47 public packages and 685 pages. Workspace types, manifests and the active Finf package policy passed. All nine package measurement rows matched the parent. Eleven selected Contents, Dialog and Runtime Tabs cases and the trusted Header first-frame controls at 320px and 390px passed. The checked public article retained nine CodeExamples. Both original bilingual S4 cases still exceeded the 60-second readiness assertion before Dialog, preserving 1,268 previews per locale and the 150-second case limit. This fix improves native text selection preservation; matrix startup acceptance remains open.
