# Collection item position from one Anatomy order read

The production Search CPU profile measured repeated Anatomy ordering in Collection item position reads. Each read requested a sorted index and separately requested the same ordered role list for the total. The change reads that list once and locates the current logical instance through the existing opaque Anatomy port identities. Missing domains, role isolation, ordering and the index, total, first and last results retain their existing behavior.

With the exact final test bytes applied to current main, the original module calls the second order query once and the regression fails. The exact signed candidate `3fae13bf85dd618836e55cb2ef62cc5a382b4894` passed 161 tests in 12 files and both workspace and Docs type checks. The exact package was packed locally and its compiled entry was checked. The coverage audit reported the same 1614 inherited diagnostics as main.

Two production A/B controls on the Search candidate plus this exact product source change reduced real DOM position comparisons from 2,081,253 to 1,112,569 on both rounds. All 97 result rows and their text/order matched. The measured rows had no position or set-size ARIA attributes in this control. The last getter returned about 309ms and 384ms sooner. The original 1000ms window was still missed.

The separate clean signed candidate also built the actual Docs and generated Pagefind index, recovered from the controlled index HEAD503, and retained 97 real result rows on both routes. Its supplemental 1000ms window remained red. The image is the later React entry frame on the Brutalist route.
