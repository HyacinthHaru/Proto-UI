# Typed effect graph modeling probe

Run `node --test experiments/effect-graph/model.test.mjs`.

This inspection-only experiment asks whether two pinned real pipelines fit explicit pass/resource/source/binding data without raw host objects or anonymous shader source. It copies no upstream kernel or demo asset, installs nothing and renders nothing. Every result remains `not-admitted`, even when graph structure is valid.

See [the draft ADR](../../internal/records/2026-10-03-typed-effect-graph-adr.md) for source links, exact commits, license gates, unmodeled extensions and compiler/host limits. The single-surface private resolver in #804 is reusable lifetime research, not a permanent limit on graph expressiveness.

The 2026-10-04 hardening adds malformed collection/nested-metadata diagnostics, explicit required texture sampler bindings, and type-derived byte lengths for the pinned 32-bit scalar/vector packed fields. All twenty model tests pass, including negative controls reproduced against the preceding inspector. Missing sampler metadata is invalid; a kernel with no texture input declares an empty list. Studio's bounded read-only weight buffer remains data, not a texture sampler.

Packed matrix/array layouts are rejected until their stride/layout contracts are modeled; Flutter's existing reflected float-slot arrays remain inspection data without a fabricated packed-byte ABI. Scalar/vector byte checks follow [WGSL alignment and size](https://www.w3.org/TR/WGSL/#alignment-and-size), but do not establish full target alignment, reflection or compilation. This inspector is still not a production validator or a security boundary for hostile JavaScript objects, accessors or resource-exhausting input. Physical source/format, license, host lifetime and rendering admission remain unchanged.

The subsequent review repair adds nine negative-control groups (29 model tests total): required read-only data bindings; known uniform ABI labels; declared pass ceilings; distinct named versus indexed sampler contracts; one presentation writer; known source compatibility kinds; complete repository/path pins; explicit feature-precondition modes; and nonempty member IDs. Flutter's existing host requirements are now checked under an explicit `host-required` mode. These are internal inspection contracts, not additional Prototype syntax or newly admitted rendering capabilities. The nine original malformed cases all returned success before the repair and are now rejected.

A second review pass adds six more negative-control groups (35 tests total), checking unique binding names, explicit frame-value/extent/coordinate producers, the pinned host size uniform's float slots, bounded shape capacity, known license-gate labels, and nonempty target requirements. Application frame-state declarations remain inspection data, not evidence that a runtime producer or a native backend exists. Source-specific Flutter slot and shape-layout checks belong to this pinned recipe probe; they are not cross-platform Prototype restrictions.

The third bounded review repair requires a recognized typed value binding for each reflected uniform, validates the declared pass invalidation policy and dependencies, and checks usable resource contract value shapes. These three additional negative-control groups bring the suite to 38 tests; they do not establish runtime invalidation behavior or physical GPU format support.

The fourth review repair records each pinned kernel's required invalidation contract and checks the pass against it, together with read-only target buffer access, blur-weight capacity, exact binding names, target-finite f32 constants, nonempty uniform layouts, host blend, physical texture usages and fragment draw domains. Nine more negative-control groups bring the suite to 47 tests. These source-specific metadata checks still do not execute kernels or establish complete compiler/host admission.

The fifth review pass checks application-sampler resource kinds, shader entry-point identifiers and consistent f32 data byte bounds (51 tests total). Copy/composite pass kinds remain explicitly unsupported in this two-pipeline probe until their own input/composition contracts are modeled; recognizing their names did not constitute an implemented lowering capability.

The sixth bounded review repair adds five negative-control groups (56 tests total): sampled intermediate filter/wrap contracts, recognized application texture kinds, structural screen-DPR coordinate dependencies, kernel target-profile/pass/ABI compatibility, and an explicit ordered float-slot range for every Flutter uniform. The two declared slot inventories contain 121 geometry floats and 45 render floats. These are source-derived expectations, not a claim that shader reflection or execution has run. The GLSL geometry `layout(location = 115)` is not float slot 115: the preceding vector components and 112-element array put `uNativeEdge` at float slot 120. Render ranges follow actual declarations and [the pinned Dart writes](https://github.com/sdegenaar/liquid_glass_widgets/blob/c35d7e115a52e05389dd8d98c6b32d4582931c33/lib/src/engine/rendering/liquid_glass_render_object.dart#L550), not the shader's stale slot comments.

Studio retains explicit linear/clamp-to-edge intermediate sampling. Flutter retains `FilterQuality.medium` and records the [pinned geometry-UV clamp](https://github.com/sdegenaar/liquid_glass_widgets/blob/c35d7e115a52e05389dd8d98c6b32d4582931c33/shaders/liquid_glass_render.frag#L308) as `shader-clamp-0-1`; that identifies shader behavior and does not certify an underlying GPU sampler's wrap mode. Screen DPR, matte raster DPR, logical bounds, transform and enclosing pass origin remain separate structural input roles. The finite target profiles classify only the already modeled WGSL fragment, Flutter geometry fragment and live Impeller filter paths. They introduce no new backend, high-level Prototype restriction or execution admission.
