This draft is a Proto design-language extension of [Base Toggle](/en/ui-libraries/base/toggle/). It is not an Apple Toggle replica or a claim of exact Apple optical parity.

Inactive controls request neutral regular glass with the secondary theme fill and foreground. Active selection requests regular style-fill tint from its governed primary fill, paired with the primary foreground. The underline and existing 1px ring-colored border remain non-color and geometry-stable selection feedback. Transient pointer pressing deforms the material independently of persistent active selection.

Use the page runtime selector for Web Components, React, Vue 3 and Vue 2. Bold starts inactive; Italic starts active. Click, Space and Enter request active changes. Unavailable keeps its active state while disabled. The status only observes the real Base activeChange signal.

## API

- active?: boolean: controlled selection. activeChange requests the next value; the owner may reject or apply it later.
- defaultActive?: boolean: initial uncontrolled selection, default false.
- disabled?: boolean: default false. Suppresses activation, clears transient interaction and preserves active selection.
- material?: 'auto' | 'opaque': default auto. Opaque opts out of optical enhancement.
- activeChange: `{ active: boolean }`. The Previewer uses onActiveChange to observe this outward signal; it is not a Toggle semantic prop.
- role="button" and aria-pressed reflect persistent active; exposed pressed is the transient pointer state. Focus and keyboard behavior come directly from Base Toggle.

## Material and accessibility

The shared Web provider samples only the visible application-owned canvas supplied by the Previewer. It does not capture arbitrary DOM or browser-compositor content. Missing, revoked or overlapping source paint, unknown preferences, reduced transparency, increased contrast and forced colors retain opaque fallback; reduced motion uses static optics. Disabled controls and material="opaque" also use fallback. Fallback retains the current state’s complete opaque color pair: primary/primary-foreground when active, secondary/secondary-foreground when inactive. Unsupported tint profiles also fall back instead of silently showing neutral glass. Selection remains identifiable by its underline when optical paint is unavailable; forced colors remain under the user agent’s control.

Leave room for each control’s expanded optical paint. This demo uses a 32px gap; wider controls may need more space. Overlapping paint is deliberately rejected, not treated as supported stacked glass.

[Apple's Materials guidance](https://developer.apple.com/design/human-interface-guidelines/materials) describes adapting materials to transparency and contrast preferences; [Meet Liquid Glass](https://developer.apple.com/videos/play/wwdc2025/219/) also discusses reduced motion. This prototype follows its own strict shared-provider gates and keeps readable theme fill/foreground instead of simulating unsupported optics.

The package is private and unreleased. This selected-tint slice remains a draft pending exact-head browser evidence for all four Web adapters. Evidence must pair decoded content pixels with the same frozen foreground and receipt, require nonempty samples with at least 4.5 contrast, and separately compare fixed-source neutral/tinted and tinted/zero-refraction GPU output. A transparent host background or changing image hash is not optical contrast or tint evidence. The direct-program diagnostic is algorithm-only and does not replace provider or public-page acceptance.

This slice covers text-labeled toggles. Icon-only selection needs a separately defined visible non-color marker; aria-pressed alone is not that marker. Full Compiler, GPUI/Flutter/Qt, native Apple rendering and group/morph parity remain outside this delivery.
