# 0.2.0-rc.5 release train 准备记录

日期：2026-07-25

## 背景

`0.2.0-rc.4` 发布后的仓库外人工试用发现两个阻塞问题：CLI 添加 `shadcn-dialog` 后，Web Component 默认 CloseIcon 会先于 Dialog context 连接并报错；Shadcn Switch 无论使用 preset 还是显式组合 Root 与 Thumb，checked 改变后 Thumb 都不移动。本轮在修复和回归覆盖基础上开启 `0.2.0-rc.5` 全局精确 release train，以尽快恢复人工试用。

## 本次准备范围

- 新增 draft `V-PROTO-UI-0005`，声明 `0.2.0-rc.5`、`v0.2.0-rc.5` 与 npm `next` channel。
- 将根 `VERSION`、全部公开 package manifest、内部精确依赖与 launch governance 对齐到 `0.2.0-rc.5`。
- 将 component preset context-safe 挂载与 Switch checked-state Thumb 位移修复写入双语 release notes。
- 生成并评审 `internal/releases/0.2.0-rc.5/package-bom.json`，重新生成 spec agent 投影并运行完整 `release:rehearse`。

## 合并后的发布边界

1. 本准备分支只建立发行身份与物料，不执行 npm 发布，不创建 `v0.2.0-rc.5` tag，也不把 `V-PROTO-UI-0005` 转为 `active`。
2. 准备 PR 合入 `main` 后，从合入 commit 手动运行 `Release Packages` workflow，选择 `mode=publish-all`、`profile=workspace` 与 `resume_published=false`。
3. workflow 必须先发布全部公开 package，之后才能创建 tag、GitHub prerelease 与不可变 spec snapshot。
4. 核对 npm、dist-tag、tag、GitHub Release 与 snapshot digest 后，从最新 `main` 建立独立证据分支，回填 `publishedAt`、`commit`、`specSnapshotDigest` 并激活 V 实体。
5. 面向用户的仓库 README、官网试用命令与当前版本说明在证据 PR 前继续指向已发布的 `0.2.0-rc.4`；随 rc.5 tarball 分发的 CLI README 则预先固定到自身版本。

本记录描述的是发布准备，不是发布完成证据。
